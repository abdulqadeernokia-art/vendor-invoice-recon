# Vendor Invoice Reconciliation with Power Query

An Excel workbook that decides, for every vendor invoice, whether it can be **approved**, must be **held**, or needs an **amount check**, using only Power Query and no VBA.

A collection vendor bills a monthly fee for every customer invoice it handled. Before paying, finance has to answer four questions:

1. Is every customer invoice on the vendor's bill still in a payable state?
2. Has the vendor billed the same customer invoice before? (repeat billing)
3. Has the customer already paid it? (it no longer appears in the open-items report)
4. Does the vendor's invoice total match the sum of its line fees?

The workbook joins the vendor's line details with the open-items report (Power BI export) on a **key**, applies the rules, and gives one decision per vendor invoice.

> All data in this repository is fictional and generated by `scripts/make_sample_data.py`.

## How to run

1. Download or clone this repository. Keep `Sample Inputs` next to the workbook.
2. Open `Vendor Invoice Recon.xlsx` and click **Enable Content** if Excel asks.
3. Click **Data → Refresh All**.

The workbook finds its own folder (sheet *Settings*, row *Data Folder*), so it works wherever you save it. To use other files, type a folder path into that cell.

## Query pipeline

```
PDF Converter.xlsx ──► VendorDetails ──┐
                                       ├──► Check ──► ApprovalSummary
PBI Status.xlsx ──► PBI_Data ──► PBI_Status ┘
```

| Query | What it does |
|---|---|
| [`VendorDetails`](Power%20Query%20Code/1_VendorDetails.pq) | Loads the vendor lines, renames columns using sheet *Settings*, cleans invoice numbers to text, builds the key `VendorInvoice\|CustomerInvoice`, and converts every *Date* column. |
| [`PBI_Data`](Power%20Query%20Code/2a_PBI_Data.pq) | Loads the full open-items report. |
| [`PBI_Status`](Power%20Query%20Code/2_PBI_Status.pq) | One row per customer invoice. A customer invoice with several report lines is OK only if **all** of its lines have a status listed as approvable on sheet *Status Rules*. |
| [`Check`](Power%20Query%20Code/3_Check.pq) | One row per line of the vendor invoices being checked. Flags **New / Repeat** (with the earlier vendor invoice it appeared in), joins the status, and treats *not in the report* as already paid. Result is **OK / BLOCK**. |
| [`ApprovalSummary`](Power%20Query%20Code/4_ApprovalSummary.pq) | One row per vendor invoice: counts, fee total compared with the invoiced amount, and the decision **APPROVE / HOLD / CHECK AMOUNT**. |

## Rules you can change without touching code

- **Status Rules**: which status prefixes allow approval.
- **Settings**: the column names in your source files, the fee column, and the data folder.
- **Vendor Invoice Headers**: the vendor invoices to check this month and their invoiced totals. If this table is empty, all vendor invoices are checked.
- **Details**: pick a vendor invoice in cell B1 to see all of its lines.

## Techniques shown

- Composite keys for matching across sources
- Group-and-aggregate with `Table.Group` (an invoice is OK only if all of its lines are OK)
- History lookups with `Table.NestedJoin` to find repeat billing
- Parameterising queries from Excel tables (`Excel.CurrentWorkbook`)
- File paths relative to the workbook, so the project runs on any machine
